1.

JavaScript is an assembly language. The JavaScript + HTML generate is like a .NET assembly. The browser can execute it, but no human should really care what's there.
Erik Meijer

Na stránkách Roota jsme se v článku Programovací jazyk Lua v roli skriptovacího jazyka pro WWW stránky seznámili s dvojicí po technologické stránce zajímavých projektů, které sice mají prakticky totožný cíl, ovšem jejich implementace je zcela odlišná. Mezi projekty, které byly v tomto článku popsány, patří především lua2js a lua.vm.js. Cíl obou zmíněných projektů je prakticky totožný: umožnit skriptování na straně WWW klienta (tj. na straně webového prohlížeče) s využitím programovacího jazyka Lua.

Zatímco se však v projektu lua2js používá technologie takzvaného „transcompileru/transpřekladače“ (zjednodušeně řečeno se jedná o překladač zdrojového kódu z jednoho programovacího jazyka do odlišného programovacího jazyka a nikoli do bajtkódu či do nativního strojového kódu), je v rámci projektu lua.vm.js použit zcela odlišný přístup: implementace celého virtuálního stroje programovacího jazyka Lua v JavaScriptu. V obou projektech se tak vlastně využívá praktická aplikace dnes již zcela vážně přijímané analogie tvrdící, že jazyk JavaScript pro webové aplikace je prakticky totéž co assembler pro aplikace nativní (slovo analogie je zdůrazněno naschvál :-).

Díky tomu, že jazyk Lua je relativně jednoduchý, a to jak z pohledu jeho syntaxe a sémantiky, tak i z pohledu implementace interpretru, nebude větším překvapením zjištění, že kromě obou výše zmíněných projektů vznikl další projekt, který je pravděpodobně nejpropracovanější a je vhodný i pro produkční nasazení.

2. Podpora jazyka Lua s využitím transpileru či plnohodnotného virtuálního stroje?

Již v úvodní kapitole bylo naznačeno, jakým způsobem můžeme do webových stránek zaintegrovat skripty naprogramované v jazyce Lua. Jednou z nabízených možností je využití transpileru, který převede zdrojový kód z jazyka Lua do více či méně čitelného zdrojového kódu v JavaScriptu. Na první pohled se může jednat o dobré řešení, protože vlastní převod (transpřeklad) se provede buď jednou (při nasazování projektu) nebo po příchodu na webovou stránku (taktéž jen jednou). Ovšem na druhou stranu to znamená, že ztratíme přímou vazbu na původní zdrojový kód, takže například chybová hlášení atd. budou odkazovat na transpilovaný kód. Tento nedostatek lze do jisté míry vyřešit použitím takzvaných source map, které (poněkud zjednodušeně řečeno) obsahují mapování mezi řádky původního zdrojového kódu a řádky napsané v JavaScriptu.

Poznámka: transpilerů existuje celá řada a s mnoha z nich jsme se již na stránkách Roota setkali.

Alternativní cestou je implementace celého virtuálního stroje jazyka Lua přímo ve webovém prohlížeči. Tento virtuální stroj bude – naprosto stejně, jako původní virtuální stroj psaný v céčku – překládat zdrojové kódy do bajtkódu jazyka Lua a ty budou následně vykonávány. To je řešení, které je do značné míry transparentní, ovšem platíme za něj většími nároky na strojový čas – je totiž rozdíl spustit skript psaný v JavaScriptu či přeložený do WebAssembly a spustit skript ve virtuálním stroji jazyka Lua, který běží ve virtuálním stroji JavaScriptu (nebo ve WebAssembly). Nicméně VM jazyka Lua je tak malý a interně rychlý, že to může být cena, kterou jsou někteří vývojáři ochotni zaplatit.

Poznámka: tímto směrem se vydaly i projekty PyScript, Pyodide a MicroPython. A jak již jejich název napovídá, jedná se o projekty, jejichž cílem na umožnění běhu aplikací naprogramovaných v Pythonu v prostředí webových prohlížečů, které se staly (ať již se nám to líbí nebo nelíbí) základem pro mnoho aplikací s GUI (nebo by se mělo psát spíše WUI?).

3. lua.vm.js – dobrý projekt, ale mohl by být i lepší

Na chvíli se ještě zastavme u projektu lua.vm.js. Jedná se o implementaci interpretru a vlastně i celého virtuálního stroje jazyka Lua spustitelnou v ekosystému JavaScriptu. Autoři lua.vm.js se však nesnažili o znovuobjevení kola a o implementaci vlastního virtuálního stroje, ale použili infrastrukturu Clang+LLVM+Emscripten pro překlad původního virtuálního stroje (ten je naprogramován v ANSI C) do JavaScriptu. Co to znamená v praxi? Běh skriptů je přibližně o polovinu pomalejší, než v případě použití nativního Lua VM (a ještě pomalejší v porovnání s LuaJITem), ovšem programátoři získávají stoprocentní kompatibilitu s původní implementací programovacího jazyka Lua.

Rychlost skriptů nemusí být kritická (záleží ovšem na konkrétní aplikaci). Důležitá je i velikost implementace celého virtuálního stroje. Ta přesahuje půl megabajtu, což je již poměrně hodně vysoké číslo:

$ ls -sh lua.vm.js
 
576K lua.vm.js

Poznámka: jedná se o minifikovanou verzi.

A nakonec – tento projekt se již dále nevyvíjí, i když je stále dostupný (zaarchivovaný) GitHub repositář – viz též https://github.com/daurnimator/lua.vm.js/tree/master. Pokud tedy budeme chtít psát skripty pro webové aplikace v jazyce Lua, je nutné se poohlédnout jinde. Ideovým nástupcem lua.vm.js (a to nástupcem plně funkčním a využitelným i na produkci) je projekt Fengari, kterému je věnován celý zbytek dnešního článku.

Poznámka: na obou projektech pracuje resp. pracoval stejný vývojář; dnes jeden ze sponzorů projektu Fengari.

4. Projekt Fengari se představuje

„It has a sane coercion system (I’m looking at you JS!). Nobody’s adding X new concepts to it each version (still looking at you JS), which makes it a stable and reliable language.“

Projekt Fengari (v originále φεγγάρι) má stejný cíl, jako výše zmíněný lua.vm.js, tj. umožnit běh skriptů napsaných v jazyce Lua ve webovém prohlížeči, a to bez nutnosti transpřekladu do JavaScriptu. Fengari tento problém řeší implementací interpretru, virtuálního stroje i základních knihoven v JavaScriptu. Díky pečlivému přepisu je výsledná implementace mnohem menší, než v případě lua.vm.js, o čemž se můžeme snadno přesvědčit:

$ ls -sh fengari-web.js
 
216K fengari-web.js

Poznámka: opět se jedná o minifikovanou verzi, takže porovnání s lua.vm.js je z tohoto pohledu férové.

Projekt Fengari umožňuje jak přímý zápis skriptů do webových stránek (vhodné spíše pro několikařádkové miniskripty), tak i specifikaci externích skriptů, které jsou do webové stránky načítány s využitím značky <script> s uvedením MIME typu application/lua. Navíc je možné na jediné stránce kombinovat skripty psané v jazyce Lua se skripty v JavaScriptu.

Z praktického pohledu je nejdůležitější vlastností projektu Fengari velmi jednoduchý přístup k DOMu i k API webových prohlížečů. Stručně řečeno – prakticky cokoli, co lze naprogramovat v JavaScriptu, lze realizovat i v programovacím jazyce Lua.

const vertexShaderSource = `
    attribute vec2 position;
 
    void main() {
        gl_Position = vec4(position, 0, 1);
    }
`
 
const fragmentShaderSource = `
    precision mediump float;
 
    void main() {
        gl_FragColor = vec4(0.7, 0.7, 0.0, 1);
    }
`
 
function print(message) {
    console.log(message);
}
 
// reference na objekt představující kreslicí plátno umístěné na webové stránce
const canvas = document.getElementById("web_gl_canvas");
if (!canvas) {
    throw new Error("Canvas with id 'web_gl_canvas' not found");
}
print("Canvas object retrieved");
 
// vytvoření a získání kontextu WebGL (3D grafika)
const gl = canvas.getContext("webgl");
if (!gl) {
    throw new Error("WebGL is not supported or context creation failed");
}
print("WebGL context created");
 
// vytvoření vertex shaderu
const vertexShader = gl.createShader(gl.VERTEX_SHADER);
if (!vertexShader) {
    throw new Error("Failed to create vertex shader.");
}
print("Vertex shader created");
 
// překlad vertex shaderu
gl.shaderSource(vertexShader, vertexShaderSource);
gl.compileShader(vertexShader);
if (!gl.getShaderParameter(vertexShader, gl.COMPILE_STATUS)) {
    const log = gl.getShaderInfoLog(vertexShader);
    gl.deleteShader(vertexShader);
    throw new Error(`Vertex shader compile failed: ${log}`);
}
print("Vertex shader compiled");
 
// vytvoření fragment shaderu
const fragmentShader = gl.createShader(gl.FRAGMENT_SHADER);
if (!fragmentShader) {
    throw new Error("Failed to create fragment shader.");
}
print("Fragment shader created");
 
// překlad fragment shaderu
gl.shaderSource(fragmentShader, fragmentShaderSource);
gl.compileShader(fragmentShader);
if (!gl.getShaderParameter(fragmentShader, gl.COMPILE_STATUS)) {
    const log = gl.getShaderInfoLog(fragmentShader);
    gl.deleteShader(fragmentShader);
    throw new Error(`fragment shader compile failed: ${log}`);
}
print("Fragment shader compiled");
 
// registrace obou shaderů
const program = gl.createProgram();
if (!program) {
    throw new Error("Failed to create program.");
}
print("Program created");
 
gl.attachShader(program, vertexShader);
gl.attachShader(program, fragmentShader);
print("Shaders attached to the program");
 
gl.linkProgram(program);
if (!gl.getProgramParameter(program, gl.LINK_STATUS)) {
    const log = gl.getProgramInfoLog(program);
    gl.deleteProgram(program);
    throw new Error(`Program link failed: ${log}`);
}
print("Program linked");
 
// souřadnice vrcholů trojúhelníku
const vertexes = [
   // x   y  
   -0.9, -0.8,
    0.9, -0.8,
    0.0,  0.7,
];
 
// buffer, do kterého se překopírují souřadnice bodu
const vertexBuffer = gl.createBuffer();
if (!vertexBuffer) {
    throw new Error("Failed to create buffer.");
}
print("Vertex buffer created");
gl.bindBuffer(gl.ARRAY_BUFFER, vertexBuffer);
 
const data = new Float32Array(vertexes);
gl.bufferData(gl.ARRAY_BUFFER, data, gl.STATIC_DRAW);
print("Vertex buffer filled-in by vertexes");
 
// navázání na parametr předávaný do vertex shaderu
const p = gl.getAttribLocation(program, "position");
if (p === -1) {
    throw new Error("Attribute 'position' not found in shader program");
}
print("Attribute 'position' found in shader program")
 
 
// seznam předávaný do vertex shaderu
gl.vertexAttribPointer(p,
                       2,                                // počet prvků v každém atributu
                       gl.FLOAT,                         // typ prvků
                       gl.FALSE,                         // data nejsou normalizována
                       2*Float32Array.BYTES_PER_ELEMENT, // velikost vertexu v bajtech
                       0                                 // offset
);
gl.enableVertexAttribArray(p);
 
// transformace souřadnic: z normalizovaných souřadnic na souřadnice na plátnu
gl.viewport(0, 0, canvas.width, canvas.height);
 
// nastavení barvy pro vymazání barvového bufferu
gl.clearColor(0, 0, 0, 1);
 
// vymazání barvového bufferu
gl.clear(gl.COLOR_BUFFER_BIT);
 
// spuštění programu
gl.useProgram(program);
 
// vykreslení trojúhelníku
gl.drawArrays(gl.TRIANGLES, 0, 3);
