1. Programovací jazyk Lua v roli skriptovacího jazyka pro WWW stránky (pokračování)

JavaScript is an assembly language. The JavaScript + HTML generate is like a .NET assembly. The browser can execute it, but no human should really care what's there.
Erik Meijer

Na stránkách Roota jsme se v úvodním článku Programovací jazyk Lua v roli skriptovacího jazyka pro WWW stránky (mimochodem: vyšel již před jedenácti lety) seznámili s dvojicí po technologické stránce zajímavých projektů. Mezi projekty, které byly ve zmíněném článku popsány, patří projekt lua2js a lua.vm.js. Cíl obou zmíněných projektů je prakticky totožný: umožnit skriptování na straně WWW klienta (tj. na straně webového prohlížeče) s využitím programovacího jazyka Lua.

Poznámka: jedenáct let v IT – to je celá věčnost. Ovšem ve světě jazyka Lua tomu tak není; zde se za tu dobu prakticky nic nezměnilo. A ve světě webových prohlížečů sice vznikly nové API i celé WebAssembly, ale původní koncept postavený na intepretru jediného jazyka, zůstal též zachován. A roku 2015 byl mimo jiné vydán ECMAScript 6.

Zatímco se však v projektu lua2js používá technologie takzvaného „transcompileru/transpřekladače“ (zjednodušeně řečeno se jedná o překladač zdrojového kódu z jednoho programovacího jazyka do odlišného programovacího jazyka a nikoli do bajtkódu či do nativního strojového kódu), je v rámci projektu lua.vm.js použit zcela odlišný přístup: implementace celého virtuálního stroje programovacího jazyka Lua v JavaScriptu. V obou projektech se tak vlastně využívá praktická aplikace dnes již zcela vážně přijímané analogie tvrdící, že jazyk JavaScript pro webové aplikace je prakticky totéž co assembler pro aplikace nativní (slovo analogie je zdůrazněno naschvál :-).

Díky tomu, že programovací jazyk Lua je stále relativně jednoduchý, a to jak z pohledu jeho syntaxe a sémantiky, tak i z pohledu implementace interpretru, nebude větším překvapením zjištění, že kromě obou výše zmíněných projektů později vznikl další projekt, který je pravděpodobně nejpropracovanější a je ve své současné podobě vhodný i pro produkční nasazení.

2. Podpora jazyka Lua s využitím transpileru či plnohodnotného virtuálního stroje?

Již v úvodní kapitole bylo naznačeno, jakým způsobem můžeme do webových stránek zaintegrovat skripty naprogramované v jazyce Lua. Jednou z nabízených možností je využití transpileru (transpřekladače), který převede zdrojový kód z jazyka Lua do více či méně čitelného zdrojového kódu v JavaScriptu. Na první pohled se může jednat o dobré řešení, protože vlastní převod (transpřeklad) se provede buď jednou (při nasazování projektu) nebo po příchodu na webovou stránku (taktéž jen jednou, tentokrát ovšem na straně uživatele). Ovšem na druhou stranu to znamená, že ztratíme přímou vazbu na původní zdrojový kód, takže například chybová hlášení atd. budou odkazovat na transpilovaný kód. Tento nedostatek lze do jisté míry vyřešit použitím takzvaných source map, které (poněkud zjednodušeně řečeno) obsahují mapování mezi řádky původního zdrojového kódu a řádky napsané v JavaScriptu.

Poznámka: transpilerů existuje celá řada a s mnoha z nich jsme se již na stránkách Roota setkali. Není bez zajímavosti, že mnoho transpilerů má jako cílový jazyk právě JavaScript, což souvisí s dominancí tohoto jazyka ve webových browserech.

Alternativní cestou je implementace celého virtuálního stroje jazyka Lua přímo ve webovém prohlížeči. Tento virtuální stroj bude – naprosto stejně, jako původní virtuální stroj jazyka Lua napsaný v céčku – překládat zdrojové kódy do bajtkódu jazyka Lua a ty budou následně vykonávány. To je řešení, které je do značné míry transparentní, ovšem platíme za něj většími nároky na strojový čas – je totiž rozdíl spustit skript psaný v JavaScriptu či přeložený do WebAssembly a spustit skript ve virtuálním stroji jazyka Lua, který běží ve virtuálním stroji JavaScriptu (nebo ve WebAssembly). Nicméně virtuální stroj jazyka Lua je tak malý a interně rychlý, že to může být cena, kterou jsou někteří vývojáři ochotni zaplatit.

Poznámka: tímto směrem se vydaly i projekty PyScript, Pyodide, MicroPython i Brython. A jak již jejich název napovídá, jedná se o projekty, jejichž cílem je umožnění běhu aplikací naprogramovaných v Pythonu v prostředí webových prohlížečů, které se staly (ať již se nám to líbí nebo nelíbí) základem pro mnoho aplikací s GUI (nebo by se mělo psát spíše WUI?).

3. lua.vm.js – dobrý projekt, ale mohl by být i lepší

Na chvíli se ještě zastavme u projektu lua.vm.js. Jedná se o implementaci interpretru a vlastně i celého virtuálního stroje jazyka Lua spustitelnou v ekosystému JavaScriptu. Autoři lua.vm.js se však nesnažili o znovuobjevení kola a o implementaci vlastního virtuálního stroje, ale použili infrastrukturu Clang+LLVM+Emscripten pro překlad původního virtuálního stroje (ten je naprogramován v ANSI C) do JavaScriptu. Co to znamená v praxi? Běh skriptů je přibližně o polovinu pomalejší, než v případě použití nativního Lua VM (a ještě pomalejší v porovnání s LuaJITem), ovšem programátoři získávají stoprocentní kompatibilitu s původní implementací programovacího jazyka Lua.

Rychlost skriptů nemusí být kritická (záleží ovšem na konkrétní aplikaci). Důležitá je i velikost implementace celého virtuálního stroje. Ta přesahuje půl megabajtu, což je již poměrně hodně vysoké číslo:

$ ls -sh lua.vm.js
 
576K lua.vm.js

Poznámka: jedná se o minifikovanou verzi. Velikost lze pochopitelně snížit zazipováním.

A nakonec – tento projekt se již dále nevyvíjí, i když je stále dostupný (zaarchivovaný) GitHub repositář – viz též https://github.com/daurnimator/lua.vm.js/tree/master. Pokud tedy budeme chtít psát skripty pro webové aplikace v jazyce Lua, je nutné se poohlédnout jinde. Ideovým nástupcem lua.vm.js (a nutno říci, že nástupcem plně funkčním a využitelným i na produkci) je projekt Fengari, kterému je věnován celý zbytek dnešního článku.

Poznámka: na obou projektech pracuje resp. pracoval stejný vývojář; dnes jeden ze sponzorů projektu Fengari.

4. Projekt Fengari se představuje

„It has a sane coercion system (I’m looking at you JS!). Nobody’s adding X new concepts to it each version (still looking at you JS), which makes it a stable and reliable language.“

Projekt Fengari (v originále φεγγάρι) má stejný cíl, jako výše zmíněný lua.vm.js, tj. umožnit běh skriptů napsaných v jazyce Lua ve webovém prohlížeči, a to bez nutnosti transpřekladu do JavaScriptu. Fengari tento problém řeší reimplementací interpretru, virtuálního stroje i základních knihoven v JavaScriptu. Díky pečlivému přepisu (a ne otrockému překladu s využitím Emscriptenu) je výsledná implementace mnohem menší, než v případě lua.vm.js, o čemž se ostatně můžeme snadno přesvědčit:

$ ls -sh fengari-web.js
 
216K fengari-web.js

Poznámka: opět se jedná o minifikovanou verzi, takže porovnání s lua.vm.js je z tohoto pohledu férové. A opět platí, že tento skript lze zmenšit jeho zazipováním.

Projekt Fengari umožňuje jak přímý zápis skriptů do webových stránek (což je ovšem vhodné spíše pro několikařádkové miniskripty), tak i specifikaci externích skriptů, které jsou do webové stránky načítány s využitím značky <script> s uvedením MIME typu application/lua. Navíc je možné na jediné stránce kombinovat skripty psané v jazyce Lua se skripty napsanými v JavaScriptu (a popřípadě i s dalšími jazyky – viz další text).

Z praktického pohledu je nejdůležitější vlastností projektu Fengari velmi jednoduchý přístup k DOMu i k API webových prohlížečů. Stručně řečeno – prakticky cokoli, co lze naprogramovat v JavaScriptu, lze realizovat i v programovacím jazyce Lua, i když některé jazykové konstrukce musely být v jazyce Lua nahrazeny speciálními funkcemi (příkladem je funkce new nahrazující operátor se stejným jménem v JavaScriptu).

6. Skript napsaný v jazyce Lua, který je přímo součástí webové stránky

Praktickou část dnešního článku začneme tradičně, konkrétně příkladem typu „Hello World!“. Přímo do kódu webové stránky umístíme skript naprogramovaný v jazyce Lua, který po svém spuštění vypíše do konzole webového prohlížeče zprávu. Povšimněte si, že tento skript musí mít MIME typ nastavený na application/lua:

<script type="application/lua">
    print("Hello World!")
</script>

Webová stránka navíc musí (ideálně už v rámci zpracování hlavičky) načíst i virtuální stroj jazyka Lua:

<script type="text/javascript" src="fengari-web.js"></script>

Celý první demonstrační příklad vypadá následovně:

<!doctype html>
<html>
    <head>
        <title>Hello #1</title>
        <script type="text/javascript" src="fengari-web.js"></script>
    </head>
    <body>
        <script type="application/lua">
            print("Hello World!")
        </script>
    </body>
</html>

Poznámka: funkcionalitu je možné si ověřit lokálně (VM Lua musí být v takovém případě uložena ve stejném adresáři, v jakém je i kód webové stránky) nebo na adrese https://tisnik.github.io/temp/hello1.htm

10. Objekt typu Float32Array a další typovaná pole JavaScriptu

V JavaScriptu se poměrně často setkáme s využitím typovaných polí (což je možná poněkud paradoxní s ohledem na typový systém tohoto jazyka). Jedná se o pole, jejichž prvky mají shodný datový typ a prvky jsou uloženy v kompaktním formátu kompatibilním s datovými typy zpracovávanými samotným mikroprocesorem. Typovaná pole mají následující jména:

Int8Array
Uint8Array
Uint8ClampedArray
Int16Array
Uint16Array
Int32Array
Uint32Array
Float16Array
Float32Array
Float64Array
BigInt64Array
BigUint64Array

Mohlo by se zdát, že konstrukce takového pole v jazyce Lua bude přímočará – pouze použijeme jméno datového typu jako jméno funkce, které předáme běžnou tabulku jazyka Lua. Snadno ovšem zjistíme, že tak jednoduché to není:

<!doctype html>
<html>
    <head>
        <title>Array #1</title>
        <script type="text/javascript" src="fengari-web.js"></script>
    </head>
    <body>
        <script type="application/lua">
            local Float32Array = js.global.Float32Array
            local array = Float32Array({1, 2, 3, 4})
            print(array)
        </script>
    </body>
</html>

Po načtení webové stránky do prohlížeče se do konzole prohlížeče vypíše chybové hlášení:

uncaught exception TypeError: calling a builtin typed array constructor without new is forbidden

Toto hlášení mj. říká, že je nutné použít jazykovou konstrukci new. Ta sice v Lue neexistuje, ovšem namísto konstrukce new můžeme zavolat funkci js.new, které se v prvním parametru předá třída, jejíž instance se má vytvořit, a ve druhém či dalších parametrech se předávají parametry původního konstruktoru.

<!doctype html>
<html>
    <head>
        <title>Array #2</title>
        <script type="text/javascript" src="fengari-web.js"></script>
    </head>
    <body>
        <script type="application/lua">
            local Float32Array = js.global.Float32Array
            local array = js.new(Float32Array, {1, 2, 3, 4})
            print(array)
        </script>
    </body>
</html>

<!doctype html>
<html>
    <head>
        <title>Array #2</title>
        <script type="text/javascript" src="fengari-web.js"></script>
    </head>
    <body>
        <script type="application/lua">
            local Float32Array = js.global.Float32Array
            local data = {1, 2, 3, 4}
            local array = js.new(Float32Array, data)
            for i = 1, #data do
                array[i - 1] = data[i]
            end
            print(array)
        </script>
    </body>
</html>

14. Kombinace více programovacích jazyků na jediné webové stránce

V předchozích kapitolách jsme se primárně zabývali ukázkami spouštění skriptů naprogramovaných v jazyce Lua. Ovšem zajímavé bude zjistit jak (a zda vůbec) je možné na jediné webové stránce zkombinovat skripty vytvořené v různých programovacích jazycích. Teoreticky to možné je, protože značka <script> podporuje atribut type, do něhož lze zapsat MIME typ rozpoznávaný jednotlivými virtuálními stroji. Nyní nám zbývá si tuto teorii ověřit. Kromě jazyka Lua, jehož virtuální stroj je realizován projektem Fengari, použijeme JavaScript (nativní podpora přímo v prohlížeči) a taktéž programovací jazyk Python (zde lze využít více realizací virtuálního stroje; pro jednoduchost použijeme Brython).

Poznámka: projektem Brython jsme se zabývali v článku Brython aneb použití jazyka Python ve skriptech přímo v prohlížeči.

15. 3×tisk textu a výpočet faktoriálu: verze v JavaScriptu, Pythonu a jazyce Lua

Pokusme se na jediné webové stránce spustit šest skriptů vytvořených ve třech programovacích jazycích, konkrétně v JavaScriptu, v Pythonu a taktéž v jazyce Lua. První tři skripty budou zapsány přímo v HTML kódu, zatímco další tři skripty budou načítány z webového serveru (opět nebude funkční načítání přímo ze souborů). Pro JavaScript pochopitelně není nutné dodávat žádnou další podporu. Pro Python budeme načítat VM Brythonu a pro Luu pak Fengari.

Zdrojový kód této webové stránky vypadá následovně:

<!doctype html>
<html>
    <head>
        <title>Rosetta</title>
        <script type="text/javascript" src="fengari-web.js"></script>
        <script type="text/javascript" src="https://cdn.jsdelivr.net/npm/brython@3.15.0/brython.min.js"></script>
    </head>
    <body>
        <script type="text/javascript">
            console.log("JavaScript: Hello World!");
        </script>
 
        <script type="application/lua">
            print("Lua: Hello World!")
        </script>
 
        <script type="text/python">
            print("Python: Hello World!")
        </script>
 
        <script src="factorial.js"  type="text/javascript"></script>
        <script src="factorial.lua" type="application/lua"></script>
        <script src="factorial.py"  type="text/python"></script>
    </body>
</html>

Ještě nám zbývá doplnit trojici skriptů factorial.js, factorial.lua a factorial.py. Začněme variantu faktoriálu realizovanou v JavaScriptu:

function factorial(n) {
    if (n < 0) return undefined;
    let result = 1;
    for (let i = 2; i <= n; i++) {
        result *= i;
    }
    return result;
}
 
console.log("10!=", factorial(10));

Sémanticky shodný skript, ovšem přepsaný do jazyka Lua:

function factorial(n)
    if n < 0 then
        return nil
    end
 
    local result = 1
    for i = 2, n do
        result = result * i
    end
 
    return result
end
 
print("10!=", factorial(10))

A konečně třetí sémanticky shodný skript, ovšem vytvořený v Pythonu:

def factorial(n):
    if n < 0:
        return None
    result = 1
    for i in range(2, n + 1):
        result *= i
    return result
 
print("10!=", factorial(10))

Poznámka: tuto stránku i funkci všech skriptů si můžete ověřit na adrese https://tisnik.github.io/temp/rosetta.htm.
